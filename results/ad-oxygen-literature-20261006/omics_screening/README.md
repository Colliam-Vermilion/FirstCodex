## 续跑协议

1. 先检查最新远端，读取此目录JSON和源清单；核对本批原件SHA。以已提交进度为准，不依赖聊天。
2. 下一批从 **R00651** 开始，默认取 `progress == 未开始`、按稳定ID升序的20条。下一批当前为：R00651、R00677、R00795、R00888、R00915、R01050、R01126、R01212、R01238、R01297、R01347、R01349、R01350、R01362、R01410、R01414、R01505、R01556、R01654、R01727。
3. 每篇开始写“处理中”；用旧解析时必须同源SHA，新增解析增量存parsed；扫描/乱码需OCR或看原页。阅读完整方法，阳性或疑似再追正文/已有附件所有数据声明位置。已完成的不重筛；“待确认”另行复核；不能将未完成标完成。
4. 每篇完成立即原子写入`evidence.json`及`screening_records.json`，记录完成日志；项目新增多行，不把单条序列/样本/run叫项目。项目去重键为数据库+规范项目号，无项目号不推断独立数据集。
5. 目标或疑似编号先存文中证据，再查官方元数据中的题名、样本、library strategy和公开状态；同篇16S编号不能误当目标组学。公开/受限/可索取/缺声明分别记，不下载reads，不联系作者。
6. `python omics_screening/scan_parsed.py`仅生成定位日志；`python omics_screening/build_outputs.py`从累计JSON重建CSV/Excel/统计。两个脚本都不自动作科学判断，不覆盖人工JSON。
7. 批末核验证据SHA/页码、队列互斥统计及Excel可打开；提交并推送原结果分支，再独立从远端取回本批文件核验。若资源不足，优先提交已完成部分，剩余保持未完成。
